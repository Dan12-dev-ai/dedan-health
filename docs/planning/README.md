# Planning Documents — NOT authoritative

> ## ⚠️ These documents describe intent, not the system
>
> Everything in this directory is **historical planning material**. It is kept
> for context and provenance only. **Do not read it as a description of what
> DEDAN Health does.**
>
> These files predate the verified implementation and contain forward-looking
> targets, roadmaps, and capability descriptions that were **never realised**.
> Several claims in them are explicitly untrue of the current code — including
> uptime figures, availability targets, and capability lists that assume
> authentication, persistence, and retrieval systems that do not exist.
>
> **For what this repository actually does, read instead:**
>
> - [../architecture.md](../architecture.md) — verified components
> - [../api.md](../api.md) — real endpoints and schemas
> - [../security.md](../security.md) — what is and is not protected
> - [../evidence-citation-registry.md](../evidence-citation-registry.md) —
>   citations, not retrieval
> - [../../README.md](../../README.md) — current status
>
> The authoritative list of known limitations is in the
> [CHANGELOG](../../CHANGELOG.md). Where these documents and the code disagree,
> **the code is correct and these documents are aspirational.**
